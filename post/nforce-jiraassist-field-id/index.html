名字会变，id 不会

2026.11.26 · 1 分钟

三个一键按钮（PCD / LTS / CVP7）都要先写一个 Product 字段。上一版是这么写的：

const RECIPE_FIELD_NAME = 'Product (CG)';

注释里的理由是我自己写的：

名字是人能在 Jira 里核对的，id 换台实例就变了。

这一版改成：

const RECIPE_FIELD_ID = 'customfield_13200';

同一个位置，相反的决定。理由不是"用户让我改"，而是上一版的理由只对了一半。

名字在两处都不稳定，只在一处稳定#

「id 换实例会变」这句话是对的——customfield_13200 在另一台 Jira 上可能是别的字段。但它漏了另一半：

名字在同一个实例里也会变。

Jira 的字段名不是字段的属性，是这块屏幕（screen / 项目配置）上的标签。同一个 custom field，在项目 A 的编辑界面上叫 Product (CG)，在项目 B 上可能叫 Product，在另一个视图里可能叫 LOB / Product。改一次字段配置，代码就写进了一个"没人读"的字段——而且不报错，因为按名字找得到某个字段，只是不是那个。

所以对照一下：

换实例改屏幕配置
名字可能还在，也可能不在会变
id会变不变

这张表决定了一个工程判断：这个扩展只服务这一台 Jira，所以"换实例"是假设，“改配置"是必然。 按假设写代码、忽略必然，就是说反了。

名字换成 id，但校验没去掉#

改成 id 不等于"盲写”。写入前仍然会把 id 拿去站点的字段目录里解析：

const field = await resolveCategoryField(settings, RECIPE_FIELD_ID);

这个函数先按 id 找，找不到才按名字找，找不到就报 This site has no field called "customfield_13200"。所以：

  • 字段被删了 → 立刻失败，报的是那个 id
  • 字段还在但被改名 → 照常工作（这正是这次想要的效果）
  • 换了一台实例、号码不同 → 报错，报的是那个号码，一眼能看出是配置问题而不是权限问题

如果直接 updateIssue({ customfield_13200: ... }) 而不解析，Jira 对不存在的字段会返回一句很含糊的 400，得靠猜。一次目录请求换一个能读懂的报错，值。

顺带说清楚"读-并-写"为什么还在#

改字段 id 不影响 labels 那段的逻辑：labels 仍然是先读再并，因为 Jira 的字段写是替换语义。这两个"防静默损坏"的动作是同一类：

  • labels 不并 → 清掉别人的标记
  • 字段不校验 → 写进没人读的字段

两者都不会报错，都会在几周后由某个人问「这张票为什么没进报表」才发现。

结果#

  • 659 组断言（配方那条改成断言 customfield_13200）
  • 297 个变异全部命中
  • check / build / verify（真 Chrome，十页）全绿

版本 v1.14.27。
