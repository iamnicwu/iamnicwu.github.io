nForce Translate v1.8.0：多了一个「查词」引擎——海词词典

翻译引擎列表里多了第六个选项：海词词典（dict.cn）。

它和别的引擎不太一样，先说清楚边界：海词只有词典接口，没有机器翻译。

实测出来的一条硬边界#

我把它的接口挨个试了一遍（不是照着文档猜的）：

  • hello → int. (打招呼)喂；你好
  • give up → v. 放弃；抛弃；戒除；交出
  • run → v. 跑；行驶；运转… / n. 路程；奔跑 / adj. 熔化的（多词性各一条）
  • 一句完整的话 → {"ok":0,"err":"您还没有任何翻译历史记录"}
  • I love you → 我 爱 你（逐词硬拼，这是假译文，不能当结果给用户）
  • 中文查英文 → query 为 null，走不通

它页面上原来那个机器翻译是转调微软 Translator 的旧 appId，那条路早就废弃了（capi.dict.cn/fanyi.php 现在返回空串）。所以「把海词当成第六个翻译引擎」这件事，照字面做出来会是：选了海词，整页翻译全挂。

所以做成混合路由#

  • 单词、固定短语（≤ 4 词、没有句子标点） → 查海词，拿词性和全部义项
  • 句子、段落、中文译英文 → 原样批量交给腾讯，和以前一样快
  • 海词确实查不到这个词（比如 résumé）→ 落回腾讯，不会给你空译文
  • 海词服务本身出错（500 / 超时） → 直接报错，不悄悄换成腾讯，否则你以为在用海词

顺带把「测试翻译」按钮也改了：选海词时拿一个单词（resilient）去测。因为拿句子测等于测了腾讯，测不出海词通不通。

一条输出侧的护栏#

海词对「不是词条」的输入会返回逐词硬拼的假译文（我 爱 你），这东西出现在译文里比报错更糟。所以解析时多两道闸：结果必须是中文、且不能是「单字之间夹空格」那种拼接，否则一律当查不到处理。

怎么用#

设置 → 翻译引擎 → 海词词典。想查词就读得舒服些（有词性、有多义项）；想整页读文章，还是腾讯或有道更合适。
